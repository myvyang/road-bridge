# 国内地图接入策略

目标读者：后续继续接入真实路网、路产几何和地图服务的开发者。

## 结论

第一版使用高德地图 JS API 作为国内底图。项目内部的路产几何统一保存为 GCJ-02 坐标系，点格式为 `[经度, 纬度]`。

原因：

- 高德和腾讯在中国大陆主要使用 GCJ-02，适合作为国内路产地图的主坐标系。
- 百度使用 BD-09，直接混用会出现偏移，除非后续决定全站切百度。
- OpenStreetMap / Leaflet 的 WGS84 路线点和国内商业地图底图不能直接混用，原型阶段已经暴露出底图加载和坐标适配问题。

## 数据来源顺序

不要从地图上随手拆路。真实数据维护顺序是：

1. 建立上市路桥公司清单。
2. 从年报、招股书、公告、收费权批复、资产交易文件里确认公司资产。
3. 对每条资产维护收费期限、建造或收购成本、开通时间、收费里程、运营指标和披露口径。
4. 再为已确认的资产补地图几何。

## 几何数据规则

- `geometry.coordinateSystem` 当前只允许 `gcj02`。
- `geometry.path` 为 `[lng, lat][]`，不要再使用 Leaflet 常见的 `[lat, lng]`。
- 如果来源是 GPS/WGS84 轨迹点，入库前要通过合规地图服务做 WGS84 到 GCJ-02 转换。
- 如果来源是百度 BD-09，必须先明确转换链路和许可，再入库。
- 线路核验状态放在内部采集台账，不放到公开地图 UI。
- 未确认的收费期限、成本、收入、车流等事实字段在公开 UI 中留空，避免把研究过程展示成路产事实。

## 合规边界

- 不抓取或复制地图服务商未授权的道路矢量数据。
- 地图底图通过官方 JS API 加载，Key 通过环境变量配置。
- 真实路线几何优先来自公司披露、政府公开文件、授权数据或手工核验点位；每条资产保留来源状态。

## 当前实现

- `NEXT_PUBLIC_AMAP_KEY` 存在时，首页加载高德 JS API 并绘制路产折线。
- `NEXT_PUBLIC_AMAP_SECURITY_CODE` 可选，用于需要安全密钥的高德 Web 端配置。
- Key 缺失或高德加载失败时，首页使用本地兜底图展示同一批路产线，保证资产选择和右侧详情仍可用。
