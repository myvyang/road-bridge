# 经验记录

- 路桥公司是收费权资产组合。估值和风险判断必须落到单条路产的收费期、剩余年限、车流、货车占比、收入、利润和扩建投入。
- 数据组织应先公司、再公司资产、再地图几何。地图页只围绕单条路产展示，股票页只做资产清单。
- 地图画布上不能放大面积筛选卡片或路产横条，否则地图本身会失去主视觉；筛选入口应放在侧栏或独立页面。
- 国内路产地图不能继续沿用 OSM/WGS84 默认假设。高德和腾讯适合按 GCJ-02 接入，百度是 BD-09；项目内部必须先统一坐标系再画线。
- 外部地图服务可能加载失败。原型阶段必须有本地视觉兜底，避免用户看到纯灰底后无法判断线路位置。
- 年报常把多条路合并披露。没有官方拆分时，应明确“合并披露”，不要为了地图或表格完整强行分摊。
- 地图展示会天然给人“事实已确认”的感觉；样例、待核验和已核验状态必须在界面上显式区分。
- 发布目标是 GitHub Pages 时，项目必须保持可静态导出；不要引入依赖运行时服务端的页面能力。
- GitHub Actions 运行在公网环境，`package-lock.json` 不能保留内网 npm registry URL；项目应通过 `.npmrc` 固定使用 `https://registry.npmjs.org/`。
