# 经验记录

- 路桥公司是收费权资产组合。估值和风险判断必须落到单条路产的收费期、剩余年限、车流、货车占比、收入、利润和扩建投入。
- 数据组织应先公司、再公司资产、再地图几何。地图页只围绕单条路产展示，股票页只做资产清单。
- 地图画布上不能放大面积筛选卡片或路产横条，否则地图本身会失去主视觉；筛选入口应放在侧栏或独立页面。
- 国内路产地图不能继续沿用 OSM/WGS84 默认假设。高德和腾讯适合按 GCJ-02 接入，百度是 BD-09；项目内部必须先统一坐标系再画线。
- 外部地图服务可能加载失败。原型阶段必须有本地视觉兜底，避免用户看到纯灰底后无法判断线路位置。
- 年报常把多条路合并披露。没有官方拆分时，应明确“合并披露”，不要为了地图或表格完整强行分摊。
- 单家公司拆解应先做财报勾稽：公司总额、业务分部、路产披露单元和未解释差额要能对上。楚天高速 2025 年路桥运营收入和成本可由 6 个披露单元完整勾稽，但汉宜、黄咸仍是多路段合并披露。
- “利润”需要谨慎分层。路段通常只能确认收入、成本、毛利和毛利率；归母净利润、财务费用、所得税、总部费用和少数股东损益不能反推到单条路。
- 在建和改扩建项目应作为路产相关但非通行费口径单独记录。建造服务收入/成本、资本开支、资产减值不是单条路当期通行运营成本。
- 分析路产纯度时，剔除与自身特许经营资产建设或改扩建相关的建造服务收入和成本。建造服务单列到资本开支、特许经营资产或投资现金流桥表；第三方工程施工和机电服务按业务实质另判。
- 经营事件进入主报告需要有重要性门槛：低于 20% 的短期分流、施工或管制扰动默认不列，除非影响收费期限、资产归属、并表、REITs、政府回购、重大减值或重大资本开支。
- 地图展示会天然给人“事实已确认”的感觉；公开 UI 不展示研究备注，未确认字段留空，核验状态留在内部采集台账。
- 发布目标是 GitHub Pages 时，项目必须保持可静态导出；不要引入依赖运行时服务端的页面能力。
- GitHub Actions 运行在公网环境，`package-lock.json` 不能保留内网 npm registry URL；项目应通过 `.npmrc` 固定使用 `https://registry.npmjs.org/`。
- 当同一家公司或同一功能的缺口已经明确时，应设置闭环目标并一次性推进到“完成或官方来源不可得”，不要反复把明确任务包装成“下一步”交还给用户。
- 公司研究报告应写成完成态研究稿。报告正文只保留结论、勾稽、资产主表、收费标准、事件口径和披露边界；“本轮补充、后续追踪、入库判断、当前处理”等过程性内容只放在 session record、项目记忆或内部台账。
- 在建路产可以估算通行量，但公开页面只展示一个“基准预测值”，不展示保守/中性/乐观三档；内部台账保留预测年份、来源、口径和置信度。
