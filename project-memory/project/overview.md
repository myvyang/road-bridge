# 项目概览

`road_bridge` 是路桥 / 高速公路股票研究的地图网站。项目方向来自 `stock_analysis` 中对通行服务类公司的研究经验：不能只看公司层面利润，必须拆到单条路产、收费权资产和财报披露口径。

## 目标

- 先维护上市路桥公司清单，再维护公司下面的路产资产，最后把路产资产标到地图。
- 在地图上浏览高速公路、桥梁和城市快速路。
- 查看每条路产的归属公司链接、收费期限、剩余年限、建设或收购成本、开通时间、通行量和货车占比。
- 显示路产之间的相邻、同一走廊、同一公司和分流关系。
- 为每个股票提供独立资产清单页；股票页不带地图，点击路产回到地图选中该路。
- 后续把年报、公告、收费权批复和运营披露作为可追溯数据源。
- 建立“公司整体财报 -> 业务分部 -> 路产披露单元 -> 单条路产”的勾稽链路，解释公司财务数据中哪些直接来自收费路产，哪些来自非路产业务或未拆分项目。
- 中国大陆地图底座使用高德优先，路产几何统一按 GCJ-02 `[经度, 纬度]` 维护。
- 发布目标是 GitHub Pages：`https://myvyang.github.io/road-bridge/`。

## 边界

- 当前第一版是可交互地图原型。楚天高速和宁沪高速已进入公开资产数据；吉林高速已完成研究报告但尚未进入公开资产和地图数据。
- 地图页主维度是路产，不是股票；股票只是路产详情里的归属链接。
- 未完成公告级核验的数据不能作为投资研究结论。
- 正式数据入库前，关键字段都需要来源链接和披露口径。
- 年报合并披露的路段收入和成本不能强拆；需要先建立披露单元，再关联到单条路产。
- 建造服务、能源、智慧交通、地产、投资收益、总部费用、财务费用和资产减值等项目不能直接摊入单条路，除非公告明确披露分配口径。
- 未配置地图 Key 时页面可以使用本地兜底路线图，但这不代表真实底图或路网已经接入。
- GitHub Pages 是静态站托管，不能依赖服务端 API、Worker、D1 或运行时 SSR。
- 研究报告应是完成态研究稿，不记录本轮补充、后续追踪、入库过程等工作日志式内容；过程和来源状态放在 `.agent/records/`、`project-memory/` 或 `data/research-ledger.json`。
